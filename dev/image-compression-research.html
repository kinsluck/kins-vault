一、TinyPNG 到底做了什么

不是更聪明的编解码器，而是三个策略的组合：
  1. 按图自适应量化——不猜固定 quality，而是针对每张图的颜色/纹理分布，找到「刚好看不出差异」的那个点。
  2. 感知度量做裁判——用接近人眼的结构相似度（SSIM）而非像素差来判断「有没有变差」。
  3. 色彩量化 + 元数据剥离——24 位 PNG 降为 8 位索引色，删掉 EXIF/ICC 等冗余块。
官方宣称「最高省 80% 且无明显差异」。本方案实测在 4K 照片上可达到同等水平（最高 91.3%），且完全离线。

四、朴素做法为什么不行

做法4K 图表现问题
JPEG quality=85省 −6.3% / −7.8% 体积反而变大。重编码已压缩过的 JPEG 时，固定质量会重新引入冗余。
WebP quality=80SSIM 0.931 ~ 0.946 体积是小了，但低于 0.98 画质线，属「有损可辨」，不满足「尽可能保证清晰度」。
固定 quality 一刀切— baboon 在 SSIM 0.98 能省 49%，lena 同样 0.98 只省 28%。同一参数在不同图上质量差距巨大。

五、开发中踩到的坑（全部实测复现）

严重Pillow 的 WebP 不支持 near_lossless 参数
传 near_lossless=90 会被静默忽略，q=90 与 q=70 输出字节完全相同（实测 28416 B）。只能靠「有损 + 低 quality」逼近，别指望这个参数。
严重并发 save 同一个 Image 对象会数据竞争
Pillow 的 Image.save() 把 encoderinfo 写在 Image 对象自身上。多线程并发保存同一个对象时，libavif 会读到别的格式的参数并抛 TypeError: argument 2 must be str, not int。该异常被 except 吞掉后 AVIF 候选会静默消失，结果从 496 KB / 省 68.6% 劣化成 726 KB 且 SSIM 掉到 0.974。解法：每个线程传 work.copy()。
严重带透明图不能直接 convert("RGB") 后比对
RGBA 转 RGB 会保留全透明像素的颜色值，而有损编码器把这些看不见的像素 RGB 写成任意值。直接比对会让 SSIM 从 0.98 崩到 0.708，算法误判「有损全不可接受」而回退到无损，体积白大 5.6 倍（170 KB vs 30 KB）。解法：先合成到白底再比，并单独保留 alpha 平面。
严重缩小后再编码会得出完全相反的结论
曾想用 1024 px 代理图加速搜索，实测代理图 SSIM 反而更低（q=45 时 0.9135 vs 全尺寸 0.9809）——缩放抹平纹理后，低频误差相对平滑图像反而更显眼。代理图成了悲观估计，把 4K 图逼到质量上限。结论：编码必须始终在全尺寸进行。
重要SSIM 的采样分辨率本身就是严格度旋钮
同一对图，全尺寸 SSIM 0.9578、降到 1600 px 是 0.9809、800 px 是 0.9889。所以搜索与终校必须在同一尺度，否则阈值形同虚设。提速只能「降比对分辨率 + 抬阈值」并用终校兜底。
重要滑窗 SSIM 会内存爆炸
sliding_window_view + mean() 会物化 (H-7)×(W-7)×8×8 的数组：一张 2201×1467 图就要 1.64 GB，四通道累计 >6 GB，进程被 OOM 直接杀掉（连 traceback 都不打印）。改用积分图实现，内存降到 O(H·W)，数值完全一致（差异 0.0）。
重要进程池不能传嵌套函数
ProcessPoolExecutor 靠 pickle 传任务，闭包抛 AttributeError: Can't get local object 'compress_dir..job'，批量处理直接不可用。且 Windows 下调用方脚本还需要 if __name__ == "__main__" 保护。改用线程池，两个问题一并消除。
一般同名不同后缀会互相覆盖
lena.jpg 与 lena.png 的 stem 都是 lena，都输出 lena.avif → 后一个覆盖前一个，12 张只产出 9 个文件。解法：按输入集合预判重名并带上原后缀。
一般AVIF 会改动 alpha 通道
实测 WebP（含有损）能完整保留 alpha，AVIF 则会改动。带透明的图因此把 AVIF 排除出候选。
根本原因固定 quality 参数根本不可靠
baboon 在 SSIM 0.98 时能省 49%，lena 在同样 SSIM 只省 28%；朴素 JPEG q=85 在 4K 图上体积反而变大（省 −6.3% / −7.8%）。这就是 TinyPNG 要做「按图自适应搜索」而非固定参数的原因。

六、画质对照（1:1 像素裁剪）

七、交付物与用法

smartimg.py —— 单文件、无外部依赖（仅 Pillow / numpy / 可选 oxipng-py），已通过 40 项自检。 
# 命令行：批量压缩（保留子目录结构，默认 SSIM≥0.98）
python smartimg.py 输入目录 输出目录 --target 0.98 --workers 8

# 只要真无损（像素级一致，体积省 2~35%）
python smartimg.py 输入目录 输出目录 --lossless

# Python 调用
from smartimg import compress, compress_dir, QualityTarget
r = compress(open("a.jpg","rb").read(), QualityTarget(ssim_min=0.98))
print(r.fmt, r.size, r.ssim)        # avif 507928 0.9809
r.save("a.avif")
compress_dir("壁纸/", "壁纸_压缩/", QualityTarget(ssim_min=0.98), workers=8)
质量档位建议：0.99 极保守（几乎不可能看出）｜0.98 默认，视觉无损｜0.97 更小但极限区域可能有细微差异。
